Overview

What each part is doing right now. Every card is a link to the section that can change it.

Server

The server starts switched off. Turning it on opens the client port; turning it off closes it and stops discovery. Paired Bluetooth controllers stay connected either way, so a console does not drop when you toggle this.

Client connections
On this network (LAN, VPN, port forward)
Clients that reach this server's address directly.
Over the Internet (hole-punch or relay)
Clients introduced by the rendezvous broker.
Through a tunnel (frp, port forward, VPN)
Clients arriving via a forwarder. Set which address it delivers from under Visibility, or this admits any direct connection.

These apply the moment you change them. All off means nobody can connect. Paired Bluetooth controllers stay connected either way, so toggling these never disturbs a console mid-game.

Identity

Leave a password blank to keep it. Changing the client password disconnects connected clients — the session key is derived from it, so they must re-authenticate. The admin password guards this page; without a separate one, any player who can connect a controller can also approve clients and re-pair adapters.

Visibility

What clients type to find this server through the broker. The broker matches on this alone — the server name above is only a label in the public listing.

The address your forwarder sends from — 127.0.0.1 for an frpc running on this machine. Leave empty to accept a tunnelled client from any address, which is still gated on the tunnel toggle above.

Used only to learn this server's own public address, so it can be reported to the broker instead of the broker having to observe it — which is what lets the broker sit behind a proxy or an frp tunnel. A request carries nothing but a random id: no password, no room code, no traffic. Comma-separated; leave empty to disable.

Hidden does not mean unreachable: a client that already knows the address (or room code) still connects. The broker only ever relays — it never sees your password or your input.

Bluetooth adapters

Capacity equals the number of enabled adapters. Enable up to four. A controller is unpaired, asleep, or awake: Pair introduces it to a console, Wake asks the console it already knows to reconnect, Sleep switches it off.

Unpairs every enabled controller and switches them off, so you can pair them again one at a time.
What the console sees

The button and stick layout the console receives. This used to sit on each adapter card, which was misleading — BlueZ publishes one service record for the whole machine, so an adapter set to a different one would have sent reports in a format the console was never told to expect.

Some consoles have no pairing list — you press their pairing button and they connect to whatever they recognise as a controller. If yours never finds the gamepad, it is filtering on the advertised name and vendor; pick the identity it expects. Changing this needs a re-pair, and the vendor id applies on the next server restart. This applies to all adapters — BlueZ keeps one service record per machine, so only the name can differ between them.

Clients

Approve a client to let its controllers reach a console, then assign each controller to an adapter.

Video

Stream the console's picture to your players. Video travels straight from the capture machine to each client — it does not pass through this server.
