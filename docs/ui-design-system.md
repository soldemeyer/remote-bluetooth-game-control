# RBGC design system

One product, three front ends: two PySide6 desktop applications and a web GUI.
This is the shared language they all speak.

**The source of truth is [`common/design/tokens.py`](../common/design/tokens.py),
not this document.** Qt imports it directly; the web gets
`server/web/static/tokens.css`, generated by `tools/build_design_tokens.py` and
committed, with a test that regenerates and compares. Change a value there and
run:

```bash
python -m tools.build_design_tokens
```

A stale stylesheet is a test failure, not a browser that is quietly a different
blue from the desktop app.

---

## Where this came from

The palette was not invented. `#4c8dff`, `#3ecf8e`, `#f5a623`, `#ff5c5c` and
`#1a1d26` each already appeared as a literal in two or three of
`client/gui/app.py`, `client/gui/latency_plot.py` and
`server/web/static/style.css` — six of the eight core colours were duplicated,
agreeing by luck. This system names what existed and gives it a home, which is
also why the redesign does not look like a different product.

## Visual direction

A premium, dark, layered control centre for low-latency console gaming.
Restrained rather than loud: the picture from the console is the brightest
thing on screen, and the interface is what sits quietly around it.

**Not**: a Bootstrap admin dashboard, an RGB peripheral utility, neon
cyberpunk, or a wall of cards.

## Colour

Dark-first. These applications are used in a dim room beside a television and
glanced at mid-game.

**Deliberately not pure black.** `#0F1116` gives the layered surfaces somewhere
to sit; `#000` flattens them and makes every border look like a seam.

| Token | Value | Use |
|---|---|---|
| `background-base` | `#0F1116` | window background |
| `background-raised` | `#151822` | headers, rails |
| `background-sunken` | `#0B0D12` | wells, inset areas |
| `surface-glass` | white 5% | floating panels |
| `surface-glass-hover` | white 8% | hover |
| `surface-glass-active` | white 11% | pressed, selected |
| `surface-solid` | `#1A1D26` | dense forms, long lists |
| `surface-solid-raised` | `#222633` | inputs, wells inside cards |
| `border-subtle` | white 8% | default hairline |
| `border-strong` | white 14% | emphasis |
| `border-active` | accent 45% | focus, selection |
| `text-primary` | `#E6E9EF` | body |
| `text-secondary` | `#A8B0C2` | supporting |
| `text-muted` | `#737B8F` | metadata, hints |
| `accent-primary` | `#4C8DFF` | primary action, focus |
| `accent-secondary` | `#6FD3C7` | secondary emphasis, sparingly |
| `success` / `warning` / `error` / `info` | `#3ECF8E` / `#F5A623` / `#FF5C5C` / `#4C8DFF` | status |
| `video-backdrop` | `#05060A` | letterbox around the picture |
| `scrim` | `#05060A` 72% | under controls floating over video |

Each `*-muted` variant is the same hue at 16% for badge and banner fills.

### The two alpha syntaxes

CSS wants a `0..1` float; **Qt's stylesheet wants a percentage**. Giving Qt a
float is not an error — it reads as almost fully transparent, so the panel
renders as though the style never applied. `Color` renders both (`.css`,
`.qss`) so no call site has to remember. A test pins both forms.

## Glass

Translucent surface, hairline border, soft shadow, layered depth.

**Use it for:** floating control bars · navigation rails · dialogs · status
cards · settings panels · overlays.

**Never for:** the video surface · dense form rows · long tables · anything
behind rapidly changing content.

### The two toolkits do it differently, on purpose

| | Web | Qt |
|---|---|---|
| Effect | `backdrop-filter: blur(16px)` | translucent fill over a **static** window gradient |
| Why | GPU-composited, cheap while the region is static | **Qt has no backdrop blur.** `QGraphicsBlurEffect` re-renders its source on every repaint |

`Color.over()` flattens a glass token onto a known backdrop where a real
composite is not available or not wanted.

**Never put `backdrop-filter` over the live preview image** — it forces a
recomposite at the preview frame rate.

### Readability over video

Blur alone does not guarantee legible text: a bright frame behind a translucent
panel defeats it. Controls over video sit on `scrim` (72% opaque), not on
glass.

## Typography

System fonts only. The project ships no font and should not start — a font file
is one more thing for the PyInstaller and AppImage bundles to carry and one
more way for them to fail on somebody else's machine.

| Step | Size | Use |
|---|---|---|
| display | 24 | window / page title |
| title | 19 | section heading |
| heading | 16 | card title |
| body | 15 | default |
| label | 13 | form labels, secondary |
| meta | 12 | metadata, units, tooltips |

Weights 400 / 500 / 600. Nothing lighter than 400 on a dark background.

**Metrics use tabular numerals** (`font-feature-settings: "tnum"`). Latency and
bitrate update several times a second, and proportional digits change width as
the value changes, so the number jitters sideways while you read it.

## Spacing, radius, motion

**Spacing** `4 · 8 · 12 · 16 · 24 · 32 · 48`. Nothing off-scale.

**Radius** — not everything is maximally rounded; a 8 px control beside a 16 px
panel is what reads as designed.

| | |
|---|---|
| 8 | buttons, inputs, chips |
| 12 | cards, list rows, metric tiles |
| 16 | glass panels, drawers, rails |
| 20 | dialogs |
| pill | badges, toggles |

**Motion** — 90 ms press · 120 ms hover/focus · 180 ms panels · 240 ms view
changes, `cubic-bezier(0.2, 0, 0.2, 1)`.

**Animate `transform` and `opacity` only.** Animating geometry, or the colour
of a large area, costs a repaint per frame — and in the client that repaint
competes with the video decoder for the GIL, which was measured to matter.
Nothing animates continuously while a stream is live.

## Icons

37 icons, one grid (24×24), one weight (1.75 stroke), round caps and joins.
Source: [`common/design/icons.py`](../common/design/icons.py).

| Consumer | Delivery |
|---|---|
| Web | CSS `mask-image` data-URIs in `tokens.css`; colour follows `currentColor` |
| Qt | `render_svg(name, color=...)` → `QSvgRenderer` (already used for controller art) |

A `<symbol>` sprite was rejected: it must be inlined into the document (needing
a server-side or build-time HTML edit) or fetched (an extra request, and
`<use href="external.svg#id">` is unreliable in Safari). A mask needs neither.

**Icons are never the only label for an unfamiliar action** — pair with text or
a tooltip.

## Status language

One vocabulary in all three applications. Always **colour + icon + text** —
never colour alone, which excludes anyone who cannot distinguish it and reads
as decoration on a glance.

| State | Colour | Icon |
|---|---|---|
| Idle | `text-muted` | `power` |
| Connecting | `warning` | `refresh` |
| Connected | `success` | `link` |
| Streaming | `success` | `play` |
| Reconnecting | `warning` | `refresh` |
| Disconnected | `text-muted` | `link-off` |
| Error | `error` | `alert` |

## Interaction states

Every interactive control defines: default · hover · pressed · focused ·
selected · disabled · loading.

- **Focus is always visible** — a 2 px `border-active` ring, never removed.
  Keyboard users are not an edge case in an application driven from a sofa.
- **Disabled** is 45% opacity plus a non-interactive cursor, never colour alone.
- **Loading** replaces the label with a spinner *at the same width*, so the
  control does not resize under the pointer and move its neighbours out from
  under the next click. `withPending()` in `server/web/static/app.js` already
  does this and is the reference behaviour.
- **Destructive actions look different from primary ones.** Primary is
  accent-filled; destructive is an `error` outline that fills on hover. They
  must never differ only by colour.

Minimum hit target 32×32 px; 24 px only for dense inline controls inside a row
that is itself a target.

## Performance rules

This is a low-latency streaming product and the UI shares a process with the
decoder and the 500 Hz input loop. These are measured constraints, recorded in
[`LATENCY_OPTIMIZATION.md`](../LATENCY_OPTIMIZATION.md).

| Rule | Why |
|---|---|
| Never scale an image in `paintEvent` | `QPainter.drawImage` scaling holds the GIL: **1.81 ms p99** cost to the input loop, against **0.51 ms** for a 1:1 blit. Scaling belongs in the decoder's `reformat`. |
| No blur in Qt | `QGraphicsBlurEffect` re-renders per repaint. |
| No `backdrop-filter` over live content | Forces recomposite at the content's frame rate. |
| Do not raise the refresh rates | Client 100 ms, video server 250 ms, web 10 Hz. |
| Collapsed panels do not update | A hidden statistics panel costs nothing. |
| Never rebuild a DOM node in use | Rebuilding closed an open `<select>` and swallowed clicks — both documented in CLAUDE.md. |
| Throttle stats to ≤ 4 Hz | Faster is unreadable anyway. |

## Accessibility

- Body text meets WCAG AA on its background; `text-muted` is for metadata only
  and never for anything essential.
- Everything reachable and operable by keyboard, with a visible focus ring.
- Semantic HTML on the web; ARIA only where semantics run out (live regions for
  status, `aria-pressed` for toggles).
- Status never communicated by colour alone.
- `prefers-reduced-motion` disables transitions rather than shortening them.
